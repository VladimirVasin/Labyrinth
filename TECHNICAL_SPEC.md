# Техническое задание: Labyrinth

## 1. Назначение проекта

`Labyrinth` - Unity-проект с процедурно генерируемой 2.5D-картой лабиринта. Игрок запускает игру со стартовой сцены, выбирает размер карты в меню, после чего система генерирует лабиринт из клеток. На первом уровне обязательно есть база, отдельная точка входа в лабиринт, босс уровня и закрытый спуск на следующий уровень подземелья.

Цель первого этапа - сделать запускаемый MVP, в котором можно:

- открыть стартовую сцену и начать игру без ручной настройки в редакторе;
- выбрать размер генерируемого лабиринта перед стартом;
- увидеть сгенерированную 2.5D-карту, разделенную на клетки;
- видеть стартовые ресурсы `Пища`, `Золото`, `Дерево`, `Железо` и лимит героев в верхней HUD-плашке;
- отличать стены от проходимых клеток;
- видеть базу, отделенную небольшим участком terrain от единственного входа в лабиринт;
- исследовать лабиринт, победить босса, получить ключ спуска и открыть проход на нижний уровень;
- открыть HUD базы кликом по базе.

## 2. Платформа и технический контекст

- Движок: Unity 6000.4.7f1.
- Рендер: Universal Render Pipeline.
- UI: Unity UI / uGUI или UI Toolkit. Для MVP предпочтительно использовать один UI-подход во всем проекте.
- Управление: Input System доступен в проекте, но для MVP допустима обработка мыши через стандартные Unity-события, если это не конфликтует с выбранной схемой.
- Целевая платформа MVP: Windows / Unity Editor Play Mode.

## 3. Игровой цикл MVP

1. При запуске проекта открывается стартовая сцена.
2. Игрок видит меню выбора размера лабиринта.
3. Игрок вводит ширину/высоту карты вручную.
4. Игрок нажимает кнопку старта.
5. Игра генерирует новую карту.
6. Камера показывает базу, вход в лабиринт и часть карты.
7. Игрок может кликнуть по базе.
8. При клике по базе открывается HUD базы.
9. HUD базы показывает крупный список построек и команды развития базы.
10. Каждый герой стартует на входной клетке у лабиринта и исследует его.
11. В лабиринте всегда появляется достижимый босс.
12. После победы над боссом герой получает ключ спуска.
13. Герой может открыть закрытый спуск во второй части лабиринта и разблокировать нижний уровень.
14. После разблокировки игрок может переключаться между доступными уровнями подземелья.

## 4. Стартовая сцена

### 4.1. Обязательные требования

- В проекте должна быть сцена, запускаемая со старта.
- Сцена должна быть добавлена в Build Settings первой сценой.
- Запуск через Play Mode должен работать без необходимости вручную перетаскивать префабы или вызывать методы из Inspector.
- Стартовая сцена должна содержать bootstrap-объект, который инициализирует меню и игровой режим.

### 4.2. Рекомендуемая структура сцены

- `GameBootstrap` - точка входа сцены.
- `MainMenuUI` - UI выбора параметров генерации.
- `GameRoot` - корневой объект игрового мира, активируется после старта игры.
- `MazeRoot` - контейнер для сгенерированных объектов карты.
- `HudRoot` - контейнер для игровых HUD-панелей.
- `CameraRig` - камера 2.5D-вида.
- `EventSystem` - системный объект UI.

## 5. Меню перед началом игры

### 5.1. Функциональность

Перед генерацией карты игрок должен выбрать размер лабиринта. Меню должно появляться до начала игровой симуляции.

Минимальный набор элементов:

- заголовок проекта или режима;
- ручной ввод ширины и высоты карты;
- поле seed;
- кнопка случайного seed;
- кнопка `Начать`;
- кнопка `Назад` или `Закрыть` опционально для MVP;
- краткое отображение текущего выбранного размера.

### 5.2. Размеры карты

Главное меню использует только ручной ввод размера без кнопок готовых пресетов.

Требования:

- значения по умолчанию в полях: ширина `100`, высота `25`;
- при генерации размер нормализуется, поэтому значение `100 x 25` создает карту `101 x 25`;
- минимальный размер: ширина `21`, высота `15`;
- максимальный размер MVP: ширина `101`, высота `101`;
- ширина и высота должны приводиться к нечетным значениям, если выбран алгоритм генерации, требующий нечетной сетки;
- некорректный ввод должен блокировать старт или автоматически исправляться с понятным отображением результата.

### 5.3. Поведение после старта

- После нажатия `Начать` меню скрывается.
- Система создает карту с выбранными параметрами.
- Повторный старт новой генерации в рамках MVP необязателен, но архитектура не должна этому мешать.

## 6. Карта и сетка

### 6.1. Базовая модель карты

Карта состоит из прямоугольной сетки клеток.

Каждая клетка имеет:

- координаты `x, y`;
- тип клетки;
- флаг проходимости;
- ссылку на визуальное представление, если оно создано;
- дополнительные метаданные генерации, если нужны алгоритму.

Обязательные типы клеток:

- `Wall` - стена, непроходимая клетка;
- `Path` - проходимая клетка лабиринта;
- `Entrance` - вход в лабиринт, проходимая клетка;
- `LockedDownStairs` - закрытый спуск на следующий уровень, непроходим до получения ключа спуска;
- `OpenDownStairs` - открытый спуск на следующий уровень, проходимая клетка перехода;
- `UpStairs` - визуальная точка возврата с нижнего уровня к верхнему;
- `Base` - база, отдельный объект снаружи лабиринта, отделенный от входа небольшим участком terrain.

### 6.2. Координаты и ориентация

- Логическая карта живет в координатах сетки.
- Мир Unity строится из координат сетки через единый размер клетки, например `cellSize = 1.65`, при этом логика генерации и размещения остается в координатах сетки.
- Размеры моделей юнитов и декоративных маркеров отделены от `cellSize` и сохраняют прежний визуальный масштаб, когда увеличивается расстояние между клетками.
- Модели зданий масштабируются отдельно: замок, фермы, дома героя и лавка алхимика отображаются в строительном масштабе `x2` относительно базовой единицы моделей.
- Рекомендуемая проекция: `x` карты -> `world.x`, `y` карты -> `world.z`, высота объектов -> `world.y`.
- Это позволяет строить 2.5D-сцену с 3D-объектами и изометрической/наклонной камерой.

### 6.3. Размеры и границы

- Вся карта должна иметь внешнюю границу из стен, кроме явно заданного входа.
- Лабиринт должен быть полностью внутри области карты.
- База располагается снаружи основной области лабиринта и визуально отделена от единственного входа.

## 7. Генерация лабиринта

### 7.1. Обязательные свойства генерации

Сгенерированная карта всегда должна удовлетворять условиям:

- есть ровно один вход в лабиринт;
- вход визуально находится со стороны базы, но не входит в footprint замка;
- в середине лабиринта есть обязательная центральная комната `6 x 6`;
- центральная комната имеет ровно один вход из первой части лабиринта и ровно один выход во вторую часть;
- путь во вторую часть лабиринта и к боссу обязан проходить через центральную комнату;
- в центральной комнате появляется один мини-босс, которого нужно встретить при прохождении bottleneck-комнаты;
- внутри каждой половины лабиринта добавляются дополнительные seed-based соединения между коридорами, чтобы появлялись петли и альтернативные маршруты;
- важные цели внутри своей половины лабиринта должны иметь раннюю развилку от старта секции: вход к внешней клетке центральной комнаты, ключ центральной комнаты, спуск вниз и дальняя цель второй половины не должны держаться на единственном длинном коридоре, а второй маршрут должен открываться недалеко от входа/выхода центральной комнаты и вести к той же цели;
- есть ровно один босс;
- босс стоит на проходимой клетке, достижимой из входа;
- во второй части лабиринта есть закрытый спуск на следующий уровень, размещенный в пещере или fallback-пещере;
- спуск закрыт до победы над боссом уровня и получения ключа спуска;
- все клетки основного маршрута не заблокированы стенами;
- на картах `15 x 15` и больше лабиринт содержит открытые пещеры `3 x 3`, количество которых зависит от размера карты;
- стены и проходы визуально различимы;
- генерация не должна зависать на допустимых размерах карты.

### 7.2. Рекомендуемый алгоритм MVP

Для первого этапа рекомендуется алгоритм `Recursive Backtracker` / randomized DFS:

1. Заполнить всю карту стенами.
2. Разместить центральную комнату `6 x 6` и вертикальный разделитель, который делит лабиринт на первую и вторую часть.
3. Сгенерировать первую часть лабиринта от входа до внешней клетки входа центральной комнаты.
4. Сгенерировать вторую часть лабиринта от внешней клетки выхода центральной комнаты.
5. Открыть клетки центральной комнаты, один вход и один выход.
6. После базового DFS открыть несколько внутренних стен между уже проходимыми коридорами в первой и второй половине отдельно, не нарушая центральный разделитель.
7. После дополнительных соединений добавить несколько открытых пещер `3 x 3`, не нарушая центральный разделитель; пещеры могут иметь до двух безопасных входов.
8. После генерации выбрать вход на одной стороне карты.
9. Создать базу снаружи лабиринта, оставив между замком и входом небольшой зазор.
10. Проверить связность проходимой области и обязательность прохода через центральную комнату через BFS/DFS.
11. После генерации мобов выбрать босса в одной из наиболее удаленных достижимых зон за центральной комнатой.
12. Выбрать пещеру во второй части лабиринта для закрытого спуска; если такой пещеры нет, создать небольшую fallback-пещеру во второй части без нарушения связности.

### 7.2.1. Дополнительные соединения

После генерации DFS лабиринт не должен оставаться строго `perfect maze` с единственным маршрутом между большинством точек.

Требования:

- генератор добавляет дополнительные проходы seed-based, открывая часть стен между двумя уже проходимыми коридорами;
- количество дополнительных соединений зависит от площади карты: `round(width * height / 180)`, минимум `4`, максимум `90`;
- соединения добавляются только внутри первой или второй половины лабиринта, но не между ними;
- дополнительные соединения не должны открывать внешний край карты;
- дополнительные соединения не должны создавать обход центральной комнаты, дополнительных контактов с центральной комнатой или обход закрытых дверей;
- после первичных соединений генератор проверяет route goals и дорезает дополнительные стены рядом с ранним участком основного маршрута, пока цель не получит ранний альтернативный обход заметной длины или пока не исчерпает безопасные кандидаты;
- пещеры создаются после дополнительных соединений и могут сохранять два внешних контакта, если оба контакта находятся в той же половине лабиринта и не ломают связность/центральный bottleneck.

### 7.3. Seed

Перед стартом игры игрок должен видеть seed генерации.

Требования:

- seed задается в стартовом меню до генерации карты;
- меню позволяет сгенерировать случайный seed;
- одинаковые размер карты и seed должны давать одинаковый лабиринт;
- использованный seed сохраняется в runtime-модели результата генерации.

### 7.4. Вход

Вход должен быть единственной точкой перехода в лабиринт со стороны базы.

Требования:

- вход является проходимой клеткой;
- вход визуально отличается от обычного прохода;
- вход находится со стороны базы;
- замок располагается не на одной горизонтальной линии со входом, а немного выше него;
- footprint замка не должен касаться клетки входа, между ними должен оставаться небольшой визуальный зазор на terrain;
- от замка до входа сразу после генерации строится декоративная дорога;
- не должно быть второго скрытого прохода со стороны базы в лабиринт.

### 7.5. Босс и спуск на следующий уровень

Требования:

- отдельная финишная клетка не создается;
- поражение босса не завершает карту мгновенно, а выдает герою `Ключ спуска`;
- ключ спуска появляется только как награда за победу над боссом уровня;
- босс создается при каждой генерации;
- босс находится на проходимой клетке лабиринта;
- босс выбирается среди наиболее удаленных достижимых зон от входа во второй части лабиринта, за центральной комнатой;
- если несколько кандидатов имеют одинаковую максимальную дистанцию, выбирается случайный из них;
- босс визуально отличается от обычного моба: он крупнее и окрашен в более агрессивные цвета;
- босс не должен появляться на входе или рядом с базой.
- во второй части лабиринта создается закрытый спуск на следующий уровень;
- спуск визуально отображается как люк/лестница и отличается от обычного пола;
- герой без ключа запоминает закрытый спуск как препятствие, которое требует `Ключ спуска`;
- герой с ключом может подойти к спуску вплотную, открыть его и потратить ключ;
- открытие спуска разблокирует нижний уровень подземелья;
- после разблокировки игрок может переключаться между уровнем `1` и уровнем `2`;
- для MVP поддерживается переход только на уровень `2`, более глубокие уровни считаются будущим расширением.

Рекомендуемая логика выбора:

- после генерации выполнить BFS от входа;
- отфильтровать клетки второй части лабиринта за центральной комнатой;
- выбрать одну из самых дальних проходимых клеток среди этих кандидатов;
- создать на этой клетке босса.
- для спуска выбрать центральную клетку одной из пещер второй части, предпочтительно наиболее удаленной по достижимой дистанции от входа;
- если пещеры второй части не были созданы обычной генерацией, carved fallback-пещера должна сохранять единственный вход и не ломать центральный bottleneck.

### 7.6. Центральная комната

Центральная комната - обязательная открытая область `6 x 6` в середине лабиринта. Она является проходным узлом между первой и второй частью карты.

Требования:

- комната создается на каждой карте, минимальный допустимый размер генерации - `15 x 15`;
- все `36` клеток комнаты являются структурно открываемыми; клетки дверей на старте имеют тип закрытой двери и не проходимы для героев/мобов;
- комната встроена в вертикальный разделитель, который не позволяет обойти ее сверху или снизу;
- у комнаты ровно два внешних контакта с проходимыми клетками: один вход со стороны первой части и один выход во вторую часть;
- вход и выход находятся на противоположных сторонах комнаты и представлены дверями;
- обе двери по умолчанию закрыты, непроходимы и открываются ключом центральной комнаты;
- выходная дверь дополнительно запечатана, пока мини-босс центральной комнаты жив; после смерти мини-босса дверь открывается автоматически без ключа;
- если убрать клетки комнаты из графа проходимости, путь из входа лабиринта во вторую часть должен исчезнуть;
- `MazeGenerationResult.CentralRoom` хранит границы комнаты, внутренние клетки входа/выхода и внешние контактные клетки;
- `MazeGenerationResult.CentralDoors` хранит runtime-состояние дверей, а `CentralRoomKey` - позицию и состояние ключа.

### 7.6.1. Ключ центральной комнаты

Требования:

- один ключ центральной комнаты создается при генерации карты;
- ключ размещается в одной из обычных пещер `3 x 3` первой половины лабиринта;
- если подходящей пещеры в первой половине нет, ключ размещается fallback-логикой на дальней достижимой клетке первой половины;
- ключ подбирается рыцарем автоматически при входе на клетку ключа;
- ключ занимает пустой слот инвентаря героя;
- один ключ открывает входную дверь центральной комнаты; выходная дверь открывается автоматически после победы над мини-боссом;
- рыцарь без ключа записывает закрытую дверь в личную память как препятствие, требующее ключ;
- при построенном Доме картографа сведения о закрытой двери попадают в общую карту после возвращения рыцаря ко входу;
- рыцарь с ключом возвращается к известной ему закрытой двери, подходит вплотную и открывает ее;
- если неизвестных соседей и фронтира больше нет, рыцарь не должен переходить в остановку: с ключом он пытается открыть достижимую закрытую дверь, без цели возвращается к входу или патрулирует по личной памяти.

### 7.6.2. Сундуки в пещерах

Требования:

- каждая обычная пещера `3 x 3`, кроме пещеры с ключом центральной комнаты, содержит один сундук в центральной клетке;
- сундук открывается только один раз;
- награда сундука задается seed-based: золото `10-20`, оружие второго уровня или броня второго уровня;
- распределение наград сундука: `70%` золото, `15%` оружие второго уровня, `15%` броня второго уровня;
- оружие второго уровня - `Стальной меч`, дает `+3 к атаке`;
- броня второго уровня - `Кольчуга`, дает `+2 Armor Points`;
- когда рыцарь входит в любую клетку пещеры с закрытым сундуком, сундук открывается сразу, до ручного исследования всех клеток пещеры;
- после открытия сундука все `9` клеток этой пещеры считаются записанными в личную память открывшего рыцаря;
- XP и личное золото начисляются только за те клетки пещеры, которые были новыми для личной памяти этого рыцаря;
- открытый сундук остается лежать в пещере в открытом состоянии;
- открытие сундука сопровождается короткой анимацией крышки, всплывающим текстом найденной награды и приятным runtime-сгенерированным звуком.

### 7.7. Пещеры

Пещеры - это открытые области `3 x 3` внутри лабиринта. Они являются обычными проходимыми клетками `Path` без отдельного типа клетки.

Требования:

- пещеры добавляются после базового DFS-carving и до валидации карты;
- количество пещер зависит от площади карты: `round(width * height / 220)`, минимум `1` для карт от `15 x 15`, максимум `48`;
- на картах меньше `15 x 15` пещеры не создаются;
- центр пещеры выбирается seed-based среди внутренних координат, где область `3 x 3` не выходит за границы лабиринта;
- пещеры не должны размещаться ближе `4` клеток от входа;
- центры пещер должны быть разнесены минимум на `5` клеток;
- пещеры не должны пересекать центральный разделитель или создавать обход центральной комнаты;
- при генерации для пещеры выбирается одна дверная точка, ближайшая к входу лабиринта среди внешних контактов будущей области `3 x 3`;
- лишние внешние контакты будущей пещеры временно закрываются стенами, а кандидат принимается только если после этого все проходимые клетки лабиринта остаются достижимыми из входа;
- выбранная дверная точка определяет вход в пещеру: `CaveInfo.EntrancePosition` хранит внутреннюю клетку входа, ближайшую к существующему проходу;
- все клетки пещеры становятся `Path`;
- пещеры не должны выходить на край карты и не должны создавать дополнительные входы через внешнюю стену;
- герои, мобы и босс используют пещеры как обычные проходимые клетки.

### 7.7.1. Рудные залежи в малых пещерах

Обычные малые пещеры `3 x 3` могут содержать ресурсные залежи руды.

Требования MVP:

- руда создается только в малых пещерах, не в центральной комнате `6 x 6`;
- каждая подходящая пещера получает один тип залежи: `Iron` или `Gold`;
- шанс типа залежи: `70%` железная руда, `30%` золотая руда;
- ближайшая к входу/выходу из подземелья рудная пещера всегда принудительно становится `Iron`, чтобы первая шахта давала железо;
- если генерация создала минимум две залежи, среди них гарантированно есть хотя бы одна `Iron` и хотя бы одна `Gold`;
- залежь занимает `2-4` свободные клетки внутри пещеры;
- центр пещеры, клетка входа в пещеру, клетка ключа и клетка спуска не используются под визуал руды;
- клетки с рудой остаются проходимыми и не влияют на pathfinding;
- железная залежь может быть выбрана для шахты, которая после постройки накапливает `Железо` до партии `10` и отправляет шахтный караван в замок;
- золотая залежь может быть выбрана для шахты, которая после постройки накапливает `Золото` до партии `10` и отправляет шахтный караван в замок;
- ресурс попадает в казну только после физического прибытия шахтного каравана в замок;
- истощение залежей пока не используется, но `OreDepositModel.IsDepleted` зарезервирован для будущей добычи;
- визуал железной руды - низкие темно-серые камни с металлическими прожилками;
- визуал золотой руды - низкие темные камни с золотыми прожилками;
- генератор пишет debug-лог с количеством железных/золотых залежей.

### 7.8. Уровни подземелья

MVP поддерживает два уровня подземелья:

- уровень `1` - стартовый лабиринт с внешней базой, terrain-зоной, зданиями и входом со стороны замка;
- уровень `2` - нижнее подземелье без внешней зоны, базы, terrain-поля вокруг лабиринта и городских построек.

Требования:

- уровень `2` генерируется seed-based из тех же настроек карты, но с level-dependent seed-сдвигом, чтобы не повторять первый лабиринт один в один;
- на нижнем уровне точка появления/возврата визуально помечается лестницей вверх и ставится в той же grid-координате, где на верхнем уровне был открытый спуск вниз;
- при переключении на нижний уровень рыцарь появляется у лестницы вверх в этой координате, а не на стандартном краевом входе сгенерированной карты;
- при переключении на нижний уровень рендерится только лабиринт и его внутренние объекты;
- внешняя экономика базы остается привязана к уровню `1`;
- HUD переключения уровней появляется только после открытия спуска;
- переключение между открытыми уровнями не должно требовать новой генерации всего мира.

## 8. 2.5D-визуализация

### 8.1. Общий стиль MVP

Карта должна выглядеть как объемная 2.5D-сетка:

- пол проходов - низкие плоские тайлы;
- стены - объемные блоки/кубы или модульные стеновые сегменты;
- база - отдельный заметный объект;
- вход - проем, ворота или подсвеченная клетка;
- босс - увеличенный агрессивный вариант орка.

### 8.2. Камера

Рекомендуемая камера:

- orthographic;
- наклон сверху под углом, например `x = 45`, `y = 45`;
- видит карту как 2.5D/изометрическую сцену;
- после генерации автоматически подбирает позицию и размер под карту.

Минимальное требование:

- после старта карта, база и вход должны быть видны без ручной настройки камеры.

Управление камерой:

- колесо мыши приближает и отдаляет карту;
- `+` / `-` также приближают и отдаляют карту;
- правая или средняя кнопка мыши позволяет быстро перетаскивать обзор по карте;
- `Shift` + колесо мыши прокручивает обзор по карте;
- WASD и стрелки двигают обзор по карте;
- камера должна ограничивать перемещение разумными границами карты, чтобы игрок не терял лабиринт.

### 8.3. Объекты карты

Для MVP допустимы простые primitives:

- `Cube` для стен;
- `Plane` или тонкий `Cube` для пола;
- примитивный средневековый замок для базы;
- примитивная модель рыцаря для героя с простой анимацией ходьбы;
- примитивные модели орка и гоблина для нейтральных мобов;
- цветовые материалы для типов клеток.

Важно: визуализация должна быть отделена от логической модели карты. Генератор создает данные, renderer создает GameObject-представление.

## 9. База и HUD базы

### 9.1. База

База - стартовая точка рядом с лабиринтом. Она не является стеной и должна быть интерактивной.

Требования:

- база создается при генерации карты;
- база визуально отличается от стен и проходов и отображается как примитивный средневековый замок;
- база находится у входа;
- визуальный объем замка находится вне клеток лабиринта и не заходит на крайние клетки;
- замок стоит прямо на terrain без отдельной геометрической подложки-плиты;
- у базы есть collider или другой механизм клика;
- клик по базе открывает HUD базы.
- замок имеет `BuildingView`, но не открывает компактный MicroHUD, потому что у него есть отдельный крупный HUD базы.
- каждое физическое здание показывает читаемую world-space подпись над моделью.
- выбранное здание получает золотую обводку footprint-зоны на земле.

### 9.2. Клик по базе

Клик должен работать в Play Mode.

Рекомендуемая реализация:

- объект базы имеет `BaseView` или `BaseController`;
- камера выполняет raycast по клику мыши;
- при попадании в базу вызывается `HudController.ShowBaseHud(baseModel)`;
- при клике вне HUD или по кнопке закрытия HUD можно закрыть панель.

### 9.3. HUD базы

Минимальный HUD:

- заголовок `База`;
- крупный список зданий базы;
- строка ферм с текущим количеством, производством и стоимостью постройки;
- строка лавки алхимика со статусом и ценой зелья здоровья;
- строка часовни со статусом и диапазоном цен благословений;
- строка домов героя с текущим количеством;
- кнопка `Построить ферму`;
- кнопка `Построить лавку алхимика`;
- кнопка `Построить часовню`;
- кнопка `Создать героя`;
- кнопка закрытия.

### 9.4. MicroHUD зданий

Каждое физическое здание должно быть кликабельным и открывать компактный MicroHUD.

Требования:

- замок и все физические здания базы имеют общий компонент здания с типом, координатой, footprint и кратким эффектом;
- клик по любому зданию кроме замка через raycast показывает MicroHUD здания;
- MicroHUD показывает название, тип, текущий уровень здания и эффект здания;
- пока MicroHUD открыт, выбранное здание визуально обведено, чтобы было понятно, к какой модели относится окно;
- у зданий, которые продают предметы, дают услуги или производят ресурсы, MicroHUD содержит кнопку списка услуг; строки списка показывают цену/результат, уровень услуги при наличии, а hover рядом со строкой показывает описание с визуальной стрелкой;
- клик по замку открывает только большой HUD базы;
- клик по любому зданию кроме замка не открывает большой HUD базы.
- сундуки, золотые слитки и залежи руды кликабельны и открывают компактный MicroHUD объекта со статусом и кратким описанием;
- MicroHUD объекта скрывается при клике вне его панели или при выборе другого объекта.
- клик по модели рыцаря на карте выбирает именно этого рыцаря и открывает его HUD так же, как клик по карточке героя слева;
- выбранный рыцарь подсвечивается обводкой клетки на карте; выбранный моб или босс подсвечивается аналогичной обводкой клетки другого цвета;

Расширяемые поля на будущее:

- ресурсы базы;
- улучшения;
- список отрядов/персонажей;
- состояние экспедиции;
- команды отправки в лабиринт.

## 10. Архитектура MVP

### 10.1. Рекомендуемые runtime-компоненты

- `GameBootstrap` - управляет стартом сцены, меню и запуском генерации.
- `GameSettings` - выбранные параметры генерации.
- `MazeGrid` - логическая модель сетки.
- `MazeCell` - данные одной клетки.
- `MazeGenerator` - алгоритм создания лабиринта.
- `MazeValidation` - проверки входа и связности проходимых клеток.
- `MazeRenderer` - создание визуальных объектов карты.
- `DungeonStairsRenderer` - визуал закрытого/открытого спуска вниз и лестницы вверх.
- `BaseController` / `BaseView` - интерактивная база.
- `ResourceWallet` - текущие ресурсы игрока.
- `BaseDevelopment` - построенные базовые здания, включая фермы, дома героя, лавку алхимика, харчевню, кузницу, лазарет, лагерь лесорубов, Дом картографа и часовню.
- `BaseAmbienceController` - декоративные дороги от зданий к замку и повозки от ферм.
- `CityAmbienceController` - декоративные жители города, генерируемые от каждого построенного здания с визуальной профессией здания.
- `ResourceProductionController` - производство ресурсов от построек во времени.
- `MineConstructionController` - выбор рудных пещер, укрепление маршрута, постройка шахт и доставка железа/золота шахтными караванами.
- `TopHudView` - верхняя плашка ресурсов.
- `HeroController` - runtime-контроллер отдельного героя-исследователя.
- `HeroExplorer` - логика исследования лабиринта без знания координаты босса.
- `HeroInventory` - стартовые слоты инвентаря героя.
- `HeroBlessings` / `HeroBlessingCatalog` - единственное активное благословение рыцаря, цены и эффекты вылазки.
- `BuildingServiceCatalog` - компактные списки услуг/товаров для MicroHUD зданий с учетом текущего уровня здания, включая благословения часовни, товары лавки/харчевни/кузницы, лечение, картографию и ресурсные караваны.
- `HeroMemory` - личная память конкретного героя о разведанных клетках и известных закрытых дверях; отдельный экземпляр используется как общая карта Дома картографа.
- `HeroVisibility` / `HeroVisibilityView` - персональная текущая видимость героев, суммарная схематичная подсветка и освещение от героев или недавно погибших трупов.
- `HeroView` / `HeroMemoryView` - визуал героя и отмеченных в выбранной личной/общей памяти клеток.
- `MapHudView` / `FogOfWarView` - миникарта, большая карта по `M` и серый fog-of-war слой для уже разведанных, но сейчас не видимых клеток.
- `DungeonLevelHudView` - компактное переключение между разблокированными уровнями подземелья.
- `HeroHudView` - левые иконки героев, выбор героя и HUD выбранного героя.
- `MobController` / `MobManager` / `MobView` / `MobModel` - нейтральные мобы разных типов; текущие типы `MobSpecies.Orc`, `MobSpecies.Goblin` и `MobSpecies.Rat`, а элитность задается через `MobRank.Regular`, `MobRank.MiniBoss` и `MobRank.Boss`.
- `CombatController` / `DamageNumberView` - пошаговое сражение героя с мобом и всплывающие цифры урона.
- `MobHudView` - правый HUD выбранного моба или босса.
- `VictoryHudView` - закрываемое сообщение о победе над боссом уровня; в текущем MVP поражение босса уровня выдает ключ спуска и не завершает игру.
- `HudController` - управление HUD-панелями.
- `MainMenuUI` - меню выбора размера.
- `CameraController` - позиционирование камеры после генерации.

### 10.2. Разделение ответственности

- Генератор не должен создавать UI.
- UI не должен напрямую менять клетки карты.
- Renderer не должен решать правила генерации.
- HUD базы должен получать данные через модель/контроллер базы.
- Герой не должен получать координату босса как цель.
- Исследователь героя должен использовать только текущую клетку, соседние проходимые клетки и память посещенных клеток.
- Bootstrap должен связывать системы, но не содержать алгоритм генерации.

## 11. Данные и состояния

### 11.1. Состояния игры

Минимальные состояния:

- `MainMenu` - показ меню выбора размера;
- `Generating` - карта создается;
- `Playing` - карта создана, игрок может взаимодействовать;
- `BaseHudOpen` - открыта панель базы поверх игрового режима.

### 11.2. Настройки генерации

Минимальная модель:

- ширина;
- высота;
- seed;
- размер клетки в world units;
- введенные ширину и высоту карты.

### 11.2.1. Ресурсы игрока

Стартовые ресурсы:

- `Пища`: 50;
- `Золото`: 75;
- `Дерево`: 5;
- `Железо`: 0.

Ресурсы и лимит героев должны отображаться в верхней HUD-плашке во время игры как отдельные читаемые элементы с нарисованными иконками пищи, золота, дерева, железа и героя.

Лимит героев:

- по умолчанию максимум созданных героев равен `5`;
- улучшение замка до уровня `2` повышает лимит героев до `6`, а до уровня `3` - до `8`;
- визуальное улучшение замка добавляет железные ворота, укрепленные детали и флаги;
- в верхней HUD-плашке показывается `Герои` в формате `текущее / максимум`;
- после достижения лимита кнопка создания героя в HUD замка недоступна.

Улучшения зданий:

- в HUD замка есть отдельная вкладка `Улучшения`, где показываются текущий уровень, следующий эффект и цена;
- улучшения тратят ресурсы казны, включая `Железо`;
- максимальный уровень поддерживаемых сейчас улучшений: `3`;
- `Замок`: уровень `2` стоит `100 зол., 40 дер., 25 жел.`, уровень `3` стоит `180 зол., 80 дер., 60 жел.`;
- `Ферма`: уровень `2` стоит `50 зол., 20 дер., 15 жел.`, уровень `3` стоит `90 зол., 35 дер., 35 жел.`;
- `Лагерь лесорубов`: уровень `2` стоит `50 зол., 20 дер., 15 жел.`, уровень `3` стоит `95 зол., 35 дер., 35 жел.`;
- `Лавка алхимика`: уровень `2` стоит `70 зол., 25 дер., 20 жел.`, уровень `3` стоит `120 зол., 45 дер., 45 жел.`;
- `Харчевня`: уровень `2` стоит `65 зол., 25 дер., 18 жел.`, уровень `3` стоит `110 зол., 40 дер., 40 жел.`;
- `Кузница`: уровень `2` стоит `90 зол., 30 дер., 30 жел.`, уровень `3` стоит `160 зол., 60 дер., 70 жел.`.

Фермы:

- ферма строится кнопкой в HUD базы;
- стоимость постройки одной фермы: `25 Золото`;
- при постройке ферма физически появляется рядом с замком как отдельное примитивное здание;
- позиция фермы выбирается случайно среди свободных клеток вне логической области лабиринта;
- ферма требует свободный буфер вокруг себя относительно логической сетки, чтобы увеличенная модель не заходила на клетки лабиринта;
- ферма, дом героя, лавка алхимика и будущие здания должны полностью помещаться в границы физического terrain;
- физический terrain вокруг лабиринта имеет расширенный внешний отступ для застройки; если место рядом с замком занято, строительство продолжает искать свободную клетку дальше по внешнему периметру лабиринта;
- позиция фермы должна учитывать фактическую занятую зону замка, чтобы постройка визуально не прилипала к башням или основанию;
- между замком, фермами, лавкой алхимика и будущими зданиями сохраняется зазор минимум в 1 клетку;
- логический footprint зданий учитывает увеличенный масштаб: замок занимает радиус `3` клетки от центра, ферма занимает радиус `2` клетки от центра;
- дом героя занимает радиус `2` клетки от центра и использует те же правила свободной области и зазора между зданиями;
- лавка алхимика занимает радиус `2` клетки от центра и использует те же правила свободной области, terrain-границ и зазора между зданиями;
- каждая построенная ферма накапливает локальный запас `+1 Food` за одну игровую секунду;
- на уровне `1` локальный запас фермы копится до `10 Food`, на уровне `2` - до `15 Food`, на уровне `3` - до `25 Food`;
- когда на ферме накоплена полная партия текущего уровня, ферма отправляет повозку в замок по достроенной дороге;
- `Пища` в верхней HUD-плашке увеличивается только после того, как повозка физически доезжает до замка;
- при доставке в замок появляется всплывающая цифра `+10`;
- производство и движение повозок используют игровое время, поэтому множители `x2` и `x3` ускоряют накопление и доставку;
- при старте новой генерации ресурсы сбрасываются к `Пища: 50`, `Золото: 75`, `Дерево: 5`, `Железо: 0`, а построенные здания сбрасываются.

Лагеря лесорубов:

- лагерь лесорубов работает по той же caravan-логике, что и ферма, но добывает `Дерево`;
- на уровне `1` локальный склад дерева копится до `10`, на уровне `2` - до `15`;
- на уровне `3` лагерь добывает `+2 Дерева` за производственный тик вместо `+1`;
- визуальное улучшение добавляет железные топоры, пилу и навес для бревен.

Дома героя:

- при создании каждого героя физически строится отдельное здание `Дом героя`;
- дом героя появляется рядом с замком на свободной клетке вне логической области лабиринта;
- дом героя не имеет общей статистики с героем, но в MicroHUD показывает, для какого рыцаря был создан;
- если свободного места для дома героя нет, новый герой не создается.

Лавка алхимика:

- лавка алхимика строится кнопкой в HUD базы;
- лавка строится один раз и физически появляется рядом с замком на свободной клетке вне логической области лабиринта;
- лавка продает `Зелье здоровья` за `10` личного золота рыцаря;
- при покупке золото сразу добавляется в казну базы;
- рыцарь автоматически покупает зелья про запас, если лавка построена, у него хватает личного золота и запас меньше `3`;
- максимальный запас зелий здоровья у одного рыцаря: `3`, после улучшения лавки до уровня `3` - `4`;
- на уровне `1` зелье здоровья восстанавливает `5 HP`, после улучшения лавки до уровня `2` - `7 HP`;
- рыцарь автоматически использует зелье здоровья, когда ему не хватает минимум базового объема лечения.

Харчевня:

- харчевня продает `Паек` за `10` личного золота рыцаря и превращает `10 Пищи` из казны в один купленный паек;
- на уровне `1` паек восстанавливает `10` выносливости, после улучшения харчевни до уровня `2` - `12`;
- максимальный запас пайков у одного рыцаря: `3`, после улучшения харчевни до уровня `3` - `4`;
- визуальное улучшение добавляет печь, бочки и столы снаружи.

Кузница:

- кузница продает снаряжение только рыцарям, вернувшимся на входную клетку лабиринта;
- уровень `1` открывает покупку `Стального меча`, `Кольчуги` и `Кожаных сапог`;
- уровень `2` открывает покупку `Рыцарского меча`, `Бригантины` и `Сапог следопыта`;
- уровень `3` открывает покупку `Мастерского клинка`, `Латного доспеха` и `Сапог-скороходов`;
- MicroHUD кузницы показывает услуги текущего уровня: `Ур. 1` - `Стальной меч`, `Кольчуга`, `Кожаные сапоги`; `Ур. 2` - `Рыцарский меч`, `Бригантина`, `Сапоги следопыта`; `Ур. 3` - `Мастерский клинок`, `Латный доспех`, `Сапоги-скороходы`;
- покупка снаряжения требует только личное золото рыцаря; `Железо` используется для улучшений зданий и шахт, но не для покупки вещей;
- визуальное улучшение добавляет наковальню, печь, дым и стойку оружия.

Лазарет:

- лазарет строится кнопкой в HUD базы;
- стоимость постройки: `45 Золото`, `15 Дерево`;
- здание строится один раз и физически появляется рядом с замком на свободной клетке вне логической области лабиринта;
- рыцарь может лечиться в лазарете только при возвращении на входную клетку лабиринта;
- каждое реально восстановленное `1 HP` стоит `5 Пищи` из казны базы;
- лечение не тратит личное золото рыцаря и не создает предметы в инвентаре.

Дом картографа:

- Дом картографа строится кнопкой в HUD базы в разделе подземелья;
- стоимость постройки: `50 Золото`, `15 Дерево`;
- здание строится один раз и физически появляется рядом с замком на свободной клетке вне логической области лабиринта;
- после постройки рыцари при каждом возвращении на вход передают свою личную память карты в общую карту картографа;
- при таком же возвращении рыцарь получает обратно знания из общей карты и может использовать их для дальнейшего поиска;
- миникарта в правом нижнем углу показывает общую карту, если Дом картографа построен, иначе карту выбранного героя;
- клик по миникарте или клавиша `M` открывает большую карту.
- после постройки Дома картографа разведанные клетки отображаются через карту/fog-of-war, без отдельного слоя синих клеточных маркеров поверх лабиринта.

Часовня:

- часовня строится кнопкой в HUD базы в разделе героев;
- стоимость постройки: `55 Золото`, `20 Дерево`;
- здание строится один раз и физически появляется рядом с замком на свободной клетке вне логической области лабиринта;
- рыцари могут покупать благословения только на входной клетке лабиринта;
- благословения покупаются за личное золото рыцаря, а потраченное золото сразу попадает в казну базы;
- у одного рыцаря одновременно может быть только `1` активное благословение;
- при возвращении к входу после вылазки старое благословение очищается, после чего герой может купить новое;
- HUD рыцаря показывает отдельный параметр `Благословение` с названием активного эффекта или значением `нет`;
- hover по активному благословению в HUD рыцаря показывает описание эффекта;
- MicroHUD часовни содержит раскрываемый список всех благословений с ценами и hover-описаниями;
- hover-окна описаний в HUD должны масштабироваться по высоте, чтобы длинный текст не обрезался;
- доступны 10 благословений с ценами по полезности:
  - `Последний вздох` - `60` золота: один смертельный удар за вылазку оставляет рыцаря с `1 HP`;
  - `Золотой обет` - `40` золота: награда золотом за победу над мобами увеличена на `35%`;
  - `Свет пилигрима` - `40` золота: радиус личной видимости увеличивается на `+2` клетки;
  - `Верная рука` - `35` золота: первый удар рыцаря в каждом бою получает `+5 Attack Points`;
  - `Крепкая кость` - `30` золота: на время вылазки Max HP и текущие HP увеличиваются на `+4`;
  - `Милость картографа` - `30` золота: при сдаче знаний у входа герой уточняет клетки вокруг своей памяти во всех `8` направлениях без награды XP/золотом;
  - `Тихая поступь` - `25` золота: темный повторный спавн хуже цепляется за уже разведанный путь героя в радиусе `2` клеток;
  - `Обет возвращения` - `20` золота: возврат к входу по памяти происходит заметно быстрее, с интервалом шага `45%` от обычного;
  - `Сытный путь` - `18` золота: первый использованный паек в вылазке восстанавливает на `+7` выносливости больше;
  - `Охотник на тьму` - `15` золота: победа над мобом, появившимся повторно из темноты, дает `+8 XP`.

Окружение базы:

- после появления фермы, дома героя, лавки алхимика или другого здания от него к замку постепенно достраивается узкая декоративная дорога;
- после завершения дороги фермы отправляют маленькие повозки по этой дороге к замку только при накоплении партии `10 Food`;
- дороги и повозки являются декоративными объектами внешней зоны и не раскрывают скрытые клетки лабиринта;
- дороги строятся только по внешним клеткам terrain, не проходят через клетки лабиринта и не пересекают footprint других зданий.
- каждое построенное здание усиливает ambient-эффект города и создает своих декоративных жителей;
- жители визуально отличаются по источнику: замок создает стражников, фермы - фермеров, лагеря лесорубов - лесорубов, дома героя - оруженосцев, лачуги - крестьян, лавка алхимика - алхимиков, харчевня - трактирщиков, кузница - кузнецов, лазарет - лекарей, Дом картографа - картографов, часовня - послушников;
- ambient-жители ходят только по безопасным клеткам внешнего terrain и не заходят на клетки лабиринта или внутрь footprint других зданий.

### 11.3. Результат генерации

Результат должен содержать:

- сетку клеток;
- координату базы;
- координату входа;
- номер уровня;
- состояние спуска вниз, если он есть на уровне;
- состояние лестницы вверх, если уровень является нижним;
- список декоративных рудных залежей в малых пещерах;
- seed;
- список/массив проходимых клеток, если нужен для навигации.

### 11.4. Память героя

Каждая клетка должна иметь статус памяти:

- `не записана в памяти`;
- `записана в памяти`.

Каждый герой записывает клетку в собственную личную память только после того, как оказался на ней. До старта герой не знает координату босса и не строит маршрут к нему напрямую.

Несколько созданных героев не имеют общих статов: `HP`, `Attack Points`, `Armor Points`, личное `Золото`, `XP`, `Выносливость`, `Благословение`, инвентарь, позиция и шаги хранятся отдельно для каждого героя.
Разведанные клетки, счетчик памяти и сведения об известных закрытых центральных дверях тоже хранятся отдельно у каждого героя.
Стены, попавшие в текущую видимость героя, записываются в отдельный слой личной памяти как разведанные непроходимые клетки; они не используются для построения маршрутов и не дают XP или золото.
Общая карта появляется через Дом картографа: когда герой возвращается ко входу, он передает личные знания картографу и получает назад уже накопленные знания других героев.
Без Дома картографа герои не делятся памятью между собой.
Миникарта, большая карта и стратегический серый fog-of-war становятся доступны только после постройки Дома картографа.
На общей карте есть стратегический fog-of-war: разведанные, но сейчас не видимые клетки остаются известными, но покрываются серым слоем, а актуальные события, мобы и декоративные ресурсы в них не показываются.
После постройки Дома картографа и синхронизации у входа разведанные стены тоже попадают в общую карту и отображаются под fog-of-war отдельным темным объемным силуэтом с читаемой верхней гранью, а неизвестные стены остаются скрытыми черной темнотой.
Базовые боевые параметры рыцаря:

- HP: `10 / 10`;
- Attack Points: `10`;
- Armor Points: `0`.
Благословение рыцаря по умолчанию: `нет`.
Уровень рыцаря по умолчанию: `1`.
XP рыцаря по умолчанию: `0`.
Порог уровня `2`: `15 XP`.
Дальнейший scaling уровней использует щадящую растущую стоимость следующего уровня: уровень `3` требует `35` суммарного XP, уровень `4` - `60`, уровень `5` - `90`; цена каждого следующего уровня растет на `+5 XP`.
При каждом повышении уровня максимальная выносливость и максимальный HP героя увеличиваются на `+1`; текущая выносливость и текущий HP также получают `+1` в момент level-up.

Для MVP алгоритм исследования:

- каждый созданный герой стартует на входной клетке у лабиринта со стороны базы;
- у героя есть `Выносливость`: `10 / 10` по умолчанию;
- каждый новый уровень увеличивает максимум выносливости на `+1`;
- герой запоминает текущую клетку;
- если герой открывает новую проходимую клетку своей личной памяти, он получает `+1 XP` и `+1` личное золото без лимита;
- разведанные стены не дают личное золото и XP;
- герой выбирает соседнюю проходимую клетку, которой еще нет в его памяти, и тратит `1` выносливости при входе в новую клетку;
- движение по уже запомненным клеткам не тратит выносливость;
- если новых клеток и фронтира нет, герой не останавливается в `Stuck`, а использует fallback-поведение: дверь с ключом, возврат к входу, синхронизацию с картографом или патруль по памяти;
- герой без `Ключа спуска` запоминает закрытый спуск как известное препятствие;
- герой с `Ключом спуска` может выбрать известный закрытый спуск целью, открыть его и разблокировать следующий уровень;
- когда выносливость падает до `0`, герой возвращается к входной клетке у лабиринта только по запомненным проходимым клеткам;
- на входной клетке у лабиринта выносливость восстанавливается до `10 / 10`, после чего герой продолжает исследование;
- герой не имеет отдельного состояния нахождения финишной клетки; текущая цель уровня - победить босса, получить ключ спуска и открыть переход ниже.
- если HP героя падает до `0`, герой получает состояние `Defeated`, визуально падает и больше не исследует лабиринт;
- после смерти труп героя 5 единиц внутриигрового времени остается на карте и продолжает давать видимость вокруг себя, затем исчезает и больше не раскрывает клетки.
- визуально герой отображается примитивной моделью рыцаря;
- модель рыцаря должна быть читаемой в 2.5D: шлем, забрало, плащ, щит и меч собираются из примитивов;
- выбранный герой должен иметь визуальную отметку на карте;
- при движении у героя есть простая процедурная анимация шага.

### 11.4.1. Видимость героя

- Видимость текущих клеток хранится отдельно для каждого героя.
- Герой видит клетки в радиусе `2` клеток вокруг себя.
- Благословение `Свет пилигрима` увеличивает личный радиус видимости героя до `4` клеток.
- Видимость не проходит сквозь стены.
- Первая стена на линии видимости должна быть видима.
- Клетки за первой стеной по этой линии не видны.
- `F1` включает схематичный режим: карта остается видимой, а суммарная зона видимости всех героев и свежих трупов подсвечивается цветными маркерами.
- `F2` включает режим освещенности: клетки лабиринта вне суммарной видимости всех героев и свежих трупов скрываются, неосвещенная область внутри прямоугольника лабиринта становится полностью черной, а возле каждого такого источника видимости включается источник света.
- В режиме освещенности игрок не должен видеть клетки за стеной или за пределом радиуса видимости любого героя или свежего трупа.
- В режиме освещенности туман войны применяется только к внутренним клеткам лабиринта; крайние стены внешнего контура, terrain, здания и земля за пределами лабиринта видны всегда.
- Клетки, известные выбранному герою или общей карте картографа, но не попадающие в текущую видимость, показываются под серым слоем fog-of-war.
- Неизвестные клетки внутри лабиринта остаются полностью черными.
- В режиме освещенности мобы скрываются, если стоят вне видимых клеток.
- Все построенные здания освещают собственный footprint и `1` клетку вокруг него.
- В режиме `F2` за пределами лабиринта используется обычный terrain; отдельная сгенерированная плиточная зона между замком, фермами, домами героя и лавкой алхимика не создается.

### 11.5. Инвентарь героя

У героя должен быть базовый инвентарь.

Стартовые слоты:

- `Оружие`: `Ржавый меч`;
- `Броня`: `Обычная одежда`;
- `Обувь`: `Сандалии`;
- `Расходники`: пусто;
- `Расходники`: пусто;
- `Слот`: пусто.

HUD героя должен отображать все стартовые слоты инвентаря.
При hover по стартовому оружию HUD показывает информационную подсказку `+0 к атаке`.
При hover по стартовой броне HUD показывает информационную подсказку `0% снижения урона`.
При hover по стартовой обуви HUD показывает информационную подсказку `0% буста к скорости`.
После постройки лавки алхимика один из слотов `Расходники` может содержать `Зелье здоровья x1..x3` с подсказкой `+5 HP при использовании`; улучшение лавки меняет подсказку до `+7 HP` и на уровне `3` позволяет носить до `4` зелий.
После постройки харчевни один из слотов `Расходники` может содержать `Паек x1..x3`; улучшение харчевни меняет восстановление выносливости с `10` до `12` и на уровне `3` позволяет носить до `4` пайков.
Если герой находит в сундуке `Стальной меч`, слот `Оружие` заменяется и Attack Points увеличивается на `+3`.
Если герой находит в сундуке `Кольчуга`, слот `Броня` заменяется и Armor Points увеличивается на `+2`.
В кузнице уровня `1` герой может купить `Кожаные сапоги` за `30` личного золота с бонусом `+10%` к скорости передвижения.
После улучшения кузницы до уровня `2` герой может купить `Рыцарский меч` с бонусом `+5 Attack Points`, `Бригантину` с бонусом `+3 Armor Points` и `Сапоги следопыта` за `65` личного золота с бонусом `+20%` к скорости передвижения.
После улучшения кузницы до уровня `3` герой может купить `Мастерский клинок` с бонусом `+6 Attack Points`, `Латный доспех` с бонусом `+4 Armor Points` и `Сапоги-скороходы` за `110` личного золота с бонусом `+30%` к скорости передвижения.
Бонус обуви применяется к интервалу шага героя перед финальным множителем укрепленных клеток, поэтому ускорение укрепленных клеток остается последним бонусом движения.
Если герой повторно находит уже имеющуюся экипировку того же или более высокого уровня, он получает компенсацию `+5` личного золота.
После победы над боссом герой получает `Ключ спуска`; он занимает обычный свободный слот или заменяет уже ненужный ключ центральной комнаты, если другого свободного слота нет.

### 11.6. Мобы, босс и бой

В лабиринте должны появляться нейтральные мобы, один мини-босс центральной комнаты и один босс. Текущие реализованные типы мобов - крыса, орк и гоблин; runtime-код должен опираться на `MobSpecies` и `MobRank`, чтобы позже добавлять другие типы без переименования базовых классов.

Требования:

- обычные мобы создаются после генерации карты на проходимых клетках внутри лабиринта;
- обычные мобы не стартуют в центральной комнате, потому что она зарезервирована под мини-босса;
- количество обычных мобов зависит от числа доступных кандидатов спавна: примерно `1` моб на `38` проходимых клеток-кандидатов, минимум `4`, максимум `120`;
- крысы добавляются отдельным частым слоем первой части лабиринта до центральной комнаты: примерно `1` крыса на `22` проходимые клетки-кандидата первой части, максимум `80`;
- гоблины добавляются отдельным ранним слоем первой части после крыс: примерно `1` гоблин на `65` оставшихся кандидатов первой части, минимум до `2` при наличии места, максимум `30`;
- обычные мобы распределяются плотнее, но стартовые позиции стараются держать минимальную дистанцию `max(4, min(width, height) / 12)` от уже выбранных мобов и босса; если места не хватает, дистанция постепенно ослабляется;
- крысы меньше гоблинов визуально, имеют `12 HP`, `4 Attack Points`, `0 Armor Points`, дают `3-6` золота и `+2 XP`;
- гоблины меньше орков визуально, имеют `24 HP`, `7 Attack Points`, `2 Armor Points`, дают `7-13` золота и `+7 XP`;
- орки имеют `44 HP`, `10 Attack Points`, `4 Armor Points`, дают `14-24` золота и `+14 XP`;
- ближе ко входу чаще появляются гоблины, в средней зоне идет смешанный спавн, в дальних зонах чаще появляются орки;
- повторный спавн в темноте проверяется часто (`1.75` сек, шанс `72%`) и создает только мобов ранга `Regular`: состав зависит от общей стадии угрозы активных рыцарей, начиная с крыс/гоблинов и постепенно смещаясь к гоблинам/оркам; боссы и мини-боссы через темный respawn не появляются;
- целевой лимит регулярных мобов для темного respawn примерно на `45%` выше стартового количества обычных мобов;
- мини-босс создается в центральной комнате `6 x 6`, выбирает базовую модель одного из доступных типов мобов (`Rat`, `Goblin`, `Orc`) и визуально является увеличенной агрессивной версией этого моба, а не отдельной захардкоженной моделью;
- параметры мини-босса задаются отдельной видовой базой уровня 1: крыса-минибосс `30 HP / 5 ATK / 1 ARM`, гоблин-минибосс `48 HP / 7 ATK / 3 ARM`, орк-минибосс `72 HP / 10 ATK / 4 ARM`; на уровне `2+` текущая MVP-логика умножает HP/ATK/ARM на `x2`; награда за победу `36-64` золота и `+48 XP`;
- попадание рыцаря в центральную комнату при живом мини-боссе принудительно запускает бой, даже если рыцарь пока не подошел к нему вплотную;
- выходная дверь центральной комнаты остается запечатанной до смерти мини-босса и открывается автоматически после его поражения, поэтому пройти во вторую часть без боя нельзя;
- босс создается после генерации карты на дальней достижимой проходимой клетке внутри лабиринта;
- босс выбирает базовую модель одного из доступных типов мобов (`Rat`, `Goblin`, `Orc`) и визуально является boss-версией этого моба: крупнее, агрессивнее окрашен и получает дополнительные детали поверх базовой модели;
- мобы странствуют по лабиринту только по проходимым клеткам;
- мини-босс центральной комнаты стоит как страж и не покидает комнату обычным блужданием;
- параметры босса задаются отдельной видовой базой уровня 1: крыса-босс `78 HP / 8 ATK / 3 ARM`, гоблин-босс `104 HP / 9 ATK / 5 ARM`, орк-босс `142 HP / 12 ATK / 6 ARM`; на уровне `2+` текущая MVP-логика умножает HP/ATK/ARM на `x2`;
- по клику на моба или босса справа открывается HUD моба;
- при столкновении моба с героем начинается сражение;
- перед боем герой и моб становятся друг напротив друга на соседних клетках;
- бой идет по очереди, рыцарь всегда бьет первым;
- урон учитывает `Attack Points` атакующего и `Armor Points` цели;
- входящий по рыцарю урон снижается на его `Armor Points` по формуле `max(1, incomingDamage - ArmorPoints)`;
- за победу над обычным мобом рыцарь получает награду в зависимости от типа моба;
- за победу над боссом рыцарь получает `110-170` золота, `+125 XP` и `Ключ спуска`;
- после поражения босса игра продолжается: следующая цель - найти известный/разведать закрытый спуск и открыть его ключом;
- во время удара проигрывается короткая анимация атаки;
- над целью появляются всплывающие цифры полученного урона.

## 12. Требования к качеству

### 12.1. Надежность генерации

- Для допустимых ручных размеров генерация должна завершаться стабильно.
- Все проходимые клетки лабиринта достижимы из входа.
- Мини-босс всегда появляется на проходимой клетке внутри центральной комнаты, если центральная комната валидна.
- Босс всегда появляется на достижимой проходимой клетке во второй части лабиринта, за центральной комнатой.
- Закрытый спуск всегда появляется во второй части лабиринта и может быть открыт только после победы над боссом.
- Нижний уровень после разблокировки рендерится как подземелье без внешней базы и terrain-зоны.
- Вход всегда находится со стороны базы, но замок отделен от клетки входа и немного смещен выше входа.
- Не должно быть исключений в Console после старта игры.

### 12.2. Производительность

- Генерация карты `41 x 41` должна происходить визуально быстро в Play Mode.
- Для MVP допустима синхронная генерация, если нет заметной паузы.
- Создание объектов должно быть контролируемым: не создавать лишние объекты за пределами нужной сетки.

### 12.3. Масштабируемость

Архитектура должна позволять в следующих этапах добавить:

- игрока или отряды;
- туман войны;
- ресурсы базы;
- опасности внутри лабиринта;
- разные типы стен и комнат;
- сохранение seed;
- повторную генерацию;
- миникарту.

## 13. UX и управление

### 13.1. Меню

- Выбор размера должен быть понятным без чтения документации.
- Стартовое меню использует крупную левую HUD-панель с отдельными карточками размера карты, seed и запуска.
- Текущие параметры генерации должны читаться сразу: нормализованный размер, seed и состояние ошибок показываются рядом с соответствующими полями.
- Кнопка старта должна быть доступна только при валидных параметрах.
- Область стартового меню должна быть достаточно крупной, чтобы кнопки размера, seed и старт не выглядели тесно.

### 13.2. Игровая сцена

- Под сгенерированной картой создается физический `Unity Terrain` с `TerrainCollider`.
- Terrain пересоздается при новой генерации и удаляется при возврате в MainMenu.
- Визуально terrain выглядит как зеленая луговая земля за пределами лабиринта: используется процедурная текстура с вариациями травы, клевера, редких участков земли, мелких камней и цветочных точек, плюс легкий низкий рельеф.
- Зеленая луговая земля должна оставаться зеленой и читаемой при максимальном отдалении камеры; визуальный слой земли не должен переключаться в белый дальний LOD.
- В режиме `F2` terrain остается визуально включенным за пределами лабиринта, а темнота внутри лабиринта создается отдельной черной подложкой под сеткой клеток; физический коллайдер земли сохраняется.
- База, вход и босс должны быть различимы.
- При наведении на базу можно добавить подсветку, если это быстро реализуется.
- HUD базы должен появляться в нижнем левом углу поверх карты и не ломать управление сценой.
- HUD замка должен быть крупным и показывать только список зданий, без списка героев и без технической секции карты.
- Клавиши `1`, `2`, `3` переключают скорость времени `x1`, `x2`, `x3`.
- `F1` переключает отображение видимости на схематичную подсветку.
- `F2` переключает отображение видимости на режим освещенности со скрытием невидимых клеток лабиринта и черной неосвещенной областью только внутри границ лабиринта.
- Максимальное отдаление камеры ограничено так, чтобы карта не превращалась в нечитаемую дальнюю миниатюру.
- В правом верхнем углу должен отображаться текущий множитель времени.
- После открытия спуска должен появляться компактный HUD переключения доступных уровней подземелья.
- `Escape` из игры открывает Escape-menu поверх текущей карты и ставит игру на паузу.
- Повторное нажатие `Escape` закрывает Escape-menu и возвращает прежнюю скорость времени.
- Кнопка старта внутри Escape-menu запускает новую генерацию и только тогда очищает текущую карту.

### 13.3. HUD базы

- HUD должен открываться только при клике по базе.
- HUD должен быть крупным, с читаемым списком зданий и кнопками.
- HUD не должен показывать список героев.
- HUD должен закрываться кнопкой.
- HUD должен закрываться кликом вне его панели.
- Повторный клик по базе при открытом HUD может обновлять или оставлять панель открытой.

### 13.4. HUD героя

- После создания каждого героя в левой части экрана появляется отдельная крупная иконка-карточка героя с нарисованным образом рыцаря.
- Героя можно выбрать кликом по его карточке или по физической модели рыцаря на карте.
- При выборе героя его клетка получает желтую обводку; при выборе моба/босса его клетка получает красную обводку.
- Клик по иконке выбирает конкретного героя и открывает HUD выбранного героя.
- HUD героя показывает статус, уровень, XP, `Выносливость`, HP, личное золото, боевые параметры и инвентарь.
- HUD героя не должен перегружаться техническими строками позиции, шагов, памяти и текущей видимости.
- HUD героя показывает `HP` в формате `текущее / максимум`, `Attack Points` и `Armor Points`.
- HUD героя показывает личное `Золото` героя, стартовое значение `0`.
- HUD героя показывает уровень героя и `XP` в формате `текущее / следующий уровень`, стартовые значения `1` и `0 / 15`.
- HUD героя показывает инвентарь героя.
- Выбранный герой визуально подсвечивается на карте.
- HUD моба или босса появляется справа при клике по цели и показывает тип, состояние, HP, награду, Attack Points и Armor Points.

### 13.5. Аудио

- Музыка главного меню и внутриигровая музыка имеют раздельные уровни громкости.
- Внутриигровая музыка должна играть тише меню и не перебивать короткие игровые события.
- Внутриигровые SFX должны быть достаточно слышимыми поверх музыки.
- Runtime-аудио использует общий микшер с отдельными каналами `Music`, `SFX` и `UI`.
- Общие эффекты микшера должны поддерживать атмосферу подземелья: легкий реверб для игровых/UI-звуков и мягкая фильтрация музыкального канала без заметной мутности.
- При открытии Escape-menu или потере фокуса окна текущий внутриигровой трек ставится на паузу и затем продолжается с того же места, без автоматического переключения на следующий трек.
- Runtime-сгенерированные SFX должны покрывать основные события: постройка, создание героя, шаги героя, открытие/закрытие меню, открытие/закрытие HUD, клики/табы/подтверждения HUD, покупка расходников, покупка экипировки, использование расходников, подбор ключей, подбор/сдача слитков, открытие дверей и спуска, открытие сундуков, награда сундука, доставка еды/дерева, сбор/сдача налогов, укрепление клетки, установка факела, переключение уровня, бой, смерть, повышение уровня и победные события.

## 14. Критерии приемки MVP

MVP считается готовым, если выполнены все пункты:

- проект запускается в Unity через Play Mode со стартовой сцены;
- перед игрой отображается меню выбора размера карты;
- перед стартом можно задать или случайно сгенерировать seed;
- кнопка старта создает лабиринт выбранного размера;
- одинаковые размер и seed повторяют генерацию;
- в лабиринте есть дополнительные альтернативные проходы и петли внутри каждой половины карты, а не только один топологически верный путь;
- в верхней HUD-плашке отображаются `Пища: 50`, `Золото: 75`, `Дерево: 5`, `Железо: 0` и `Герои: 0 / 5` с отдельными иконками;
- карта состоит из клеток;
- на картах `15 x 15` и больше есть открытые пещеры `3 x 3`, созданные как проходимые клетки с одним изначальным входом;
- в малых пещерах визуально появляются железные или золотые залежи руды, которые не блокируют движение;
- построенные шахты отличаются по типу залежи и доставляют в замок железо или золото партиями через караван;
- MicroHUD построенной шахты показывает ее тип, уровень и действие улучшения: уровень `2` повышает размер партии с `10` до `15`, уровень `3` ускоряет добычу до `+2` ресурса за тик;
- под картой есть физический terrain с коллайдером;
- есть визуально различимые стены и проходы;
- есть база;
- есть ровно один вход в лабиринт со стороны базы;
- вход проходим, а footprint замка отделен от клетки входа небольшим зазором;
- замок по умолчанию стоит немного выше линии входа, и от замка до входа сразу есть декоративная дорога;
- HUD базы показывает вкладки зданий, героев, подземелья и улучшений;
- в HUD базы есть кнопка постройки фермы;
- в HUD базы есть кнопка постройки лавки алхимика;
- в HUD базы есть кнопка постройки часовни в разделе героев;
- строительные цены используют ресурсы базы: ферма `25 зол., 5 дер.`, первый лагерь лесорубов `25 зол.`, следующие лагеря лесорубов `25 зол., 10 дер.`, дом героя `25 зол., 10 пищи`, лавка алхимика `50 зол., 15 дер.`, харчевня `40 зол., 20 дер.`, кузница `60 зол., 25 дер.`, лазарет `45 зол., 15 дер.`, Дом картографа `50 зол., 15 дер.`, часовня `55 зол., 20 дер.`, Гильдия шахтёров `60 зол., 25 дер.`;
- кнопки строительства в HUD базы блокируются, если не хватает нужных ресурсов;
- после постройки `Гильдии шахтёров` в HUD замка появляется режим выбора шахты: игрок выбирает изученную малую пещеру с рудной залежью, а рабочие автоматически укрепляют маршрут от входа до выбранной пещеры;
- шахтёры выходят из гильдии по очереди, максимум `5` активных рабочих одновременно, и до замка идут строго по уже достроенной дороге от гильдии;
- дерево списывается только в замке: рабочий берет `1 дерево` на текущую клетку укрепления, идет по дороге к входу, дальше по лабиринту проходит только через уже укрепленные клетки маршрута и текущую проходимую клетку;
- перед постройкой самой шахты рабочие укрепляют не только коридор до центра выбранной минипещеры, но и все `9` проходимых клеток ее footprint `3 x 3`, после чего возвращаются к центру для финального строительства;
- после укрепления клетки шахтёр возвращается в замок тем же валидным маршрутом и может получить следующую задачу; прямые телепорт-прыжки через стены, неукреплённые клетки или неизвестные зоны запрещены;
- укрепление одной клетки маршрута стоит `1 дерево`; факел ставится не на каждой клетке, а только на укрепленной клетке у стены, если эта клетка еще не покрыта зоной света существующих факелов;
- при укреплении проходимая клетка пола получает деревянную текстуру укрепленного настила, а соседние клетки стен получают деревянную текстуру усиленной стены;
- факел освещает подземелье в радиусе `2` клетки, свет не проходит сквозь стены, а его зона добавляется к видимости в режимах `F1` и `F2`;
- построенная ферма физически появляется рядом с замком вне клеток лабиринта;
- построенная лавка алхимика физически появляется рядом с замком вне клеток лабиринта;
- рыцари могут автоматически покупать в лавке зелья здоровья за `10` личного золота до запаса `3`, а выручка сразу попадает в казну базы;
- построенный лазарет автоматически лечит рыцарей у входа, списывая `5` пищи за каждый восстановленный HP;
- построенная часовня физически появляется рядом с замком, получает дорогу, подпись, MicroHUD и освещение вокруг footprint;
- у входа рыцари автоматически покупают только `1` благословение за личное золото, а выручка попадает в казну;
- благословение действует на вылазку и обновляется при возвращении рыцаря ко входу;
- построенные здания не появляются за пределами физического terrain;
- между построенными зданиями соблюдается зазор минимум в 1 клетку;
- увеличенные модели замка и ферм визуально не заходят на клетки лабиринта;
- фермы не появляются вплотную к визуальному объему замка;
- от построенных ферм, домов героя и лавки алхимика постепенно строится узкая декоративная дорога к замку;
- от ферм отправляются маленькие повозки с партией `10 Food`, когда локальный запас фермы заполнен;
- строительство нового здания добавляет только его собственную дорогу и не пересоздает уже построенные дороги, активные повозки и ambient-жителей;
- декоративные дороги не проходят через клетки лабиринта и не пересекают другие здания;
- каждое построенное здание создает собственных ambient-жителей с визуальной профессией здания, а эти жители ходят только по внешнему terrain;
- до постройки первого здания ambient-жители у замка не отображаются;
- построенная ферма накапливает `+1 Food` за `2` игровые секунды в локальном запасе;
- `Пища` в верхней HUD-плашке увеличивается только после прибытия повозки в замок;
- всплывающая цифра пищи появляется при доставке партии в замок, а не при каждом локальном тике фермы;
- над замком появляется всплывающая цифра `+10` при доставке партии;
- каждый герой создается на входной клетке у лабиринта со стороны базы;
- можно создать несколько героев за одну генерацию карты;
- максимальное количество созданных героев по умолчанию равно `5`;
- у каждого героя отдельные статы, уровень, инвентарь, личное золото, XP и выносливость;
- разведанные клетки и память карты личные для каждого героя;
- построенный Дом картографа аккумулирует личные знания вернувшихся ко входу героев в общую карту и раздает эту карту другим вернувшимся героям;
- миникарта, большая карта по `M` и серый fog-of-war памяти скрыты до постройки Дома картографа;
- текущая видимость клеток отдельная для каждого героя;
- герой видит на `2` клетки вокруг себя, видимость не проходит сквозь стены, но первая стена видна;
- `F1` показывает схематичную подсветку суммарной зоны видимости всех героев и свежих трупов;
- новый запуск карты по умолчанию открывает лабиринт в режиме `F2`;
- `F2` скрывает неизвестные клетки лабиринта за черной темнотой, а разведанные ранее, но сейчас не видимые клетки показывает под серым fog-of-war слоем;
- разведанные стены тоже остаются видимыми под fog-of-war после появления общей карты картографа и должны читаться как отдельные темные объемы, а не сливаться с полом;
- свет факелов укрепления добавляется к видимости в режимах `F1` и `F2`;
- крайние стены внешнего контура лабиринта в режиме `F2` видны всегда;
- за пределами лабиринта terrain, замок, фермы и свободная земля видны всегда и не закрываются туманом войны;
- в режиме `F2` мобы вне видимых клеток не видны и не кликабельны;
- повторный спавн обычных мобов запрещен в зоне света героев, зданий и факелов укрепления с дополнительным отступом в 1 клетку; благословение `Тихая поступь` дополнительно защищает разведанный путь героя радиусом 2 клетки;
- в режиме `F2` маркеры выбранной личной или общей карты скрываются вне текущей освещенной области;
- замок, построенные фермы, дома героя и лавка алхимика открывают собственный footprint и `1` клетку вокруг него;
- между замком, фермами, домами героя и лавкой алхимика в режиме `F2` не создается отдельная плиточная зона: виден обычный луговой terrain;
- декоративные дороги и повозки вокруг базы остаются видимыми как часть внешней зоны и не влияют на туман войны лабиринта;
- герой ходит только по проходимым клеткам;
- у героя есть выносливость `10 / 10` по умолчанию;
- каждый новый уровень увеличивает максимум выносливости на `+1`;
- вход в новую незапомненную клетку тратит `1` выносливости;
- возврат к замку по запомненным клеткам не тратит выносливость;
- при `0` выносливости герой возвращается к входной клетке у лабиринта и восстанавливается до `10 / 10`;
- герой запоминает клетки только после прохода по ним;
- герой использует память посещенных клеток при выборе следующего шага;
- герой получает `+1 XP` и `+1` личное золото за открытие новой проходимой клетки своей личной памяти без лимита;
- герой исследует лабиринт без прямого знания координаты босса;
- после создания каждого героя слева появляется его читаемая иконка-карточка;
- клик по иконке выбирает конкретного героя и открывает HUD выбранного героя;
- HUD героя показывает боевые параметры `HP 10 / 10`, `Attack Points`, `Armor Points`;
- HUD героя показывает `Выносливость`;
- HUD героя показывает отдельный параметр `Благословение`;
- HUD героя показывает личное золото, по умолчанию `0`;
- HUD героя показывает уровень, по умолчанию `1`;
- HUD героя показывает XP до следующего уровня, по умолчанию `0 / 15`;
- HUD героя показывает слоты `Оружие`, `Броня`, `Обувь`, два слота `Расходники` и один пустой слот;
- при наличии лавки алхимика рыцарь покупает `Зелье здоровья` про запас до `3` штук и использует его при ранении, восстанавливая `5 HP`;
- в части сундуков вместо золота может быть `Стальной меч` или `Кольчуга`, и найденная экипировка меняет боевые параметры героя;
- после открытия сундука всплывающим текстом показывается найденная награда;
- выбранный герой подсвечивается на карте;
- в лабиринте появляются странствующие нейтральные мобы типов `Rat`, `Orc` и `Goblin`;
- обычных мобов становится больше на больших картах: расчет идет примерно от плотности `1` моб на `38` доступных клеток, с диапазоном `4..120`;
- крысы появляются только в ранней части лабиринта до центральной комнаты и постепенно исчезают из темного респауна по мере общей прокачки активных рыцарей;
- темный респаун меняет состав врагов по общей стадии угрозы партии: ранние стадии дают крыс и гоблинов, средние - в основном гоблинов, поздние - гоблинов и орков без крыс;
- в лабиринте появляется один усиленный босс;
- моба или босса можно выбрать кликом, его HUD появляется справа;
- HUD моба справа показывает меньше данных, чем HUD рыцаря: тип, состояние, HP, награду и боевые параметры;
- при столкновении героя и моба начинается пошаговый бой;
- рыцарь в бою наносит первый удар;
- за победу над крысой рыцарь получает `3-6` золота и `+2 XP`;
- за победу над гоблином рыцарь получает `7-13` золота и `+7 XP`;
- за победу над орком рыцарь получает `14-24` золота и `+14 XP`;
- за победу над боссом рыцарь получает увеличенную награду и `Ключ спуска`;
- после победы над боссом герой может открыть закрытый спуск во второй части лабиринта;
- после открытия спуска разблокируется уровень `2` и появляется HUD переключения уровней;
- уровень `2` рендерится как чистое подземелье без внешней базы и terrain-зоны;
- при падении HP до `0` рыцарь умирает, визуально падает, 5 единиц внутриигрового времени продолжает давать видимость вокруг трупа, затем исчезает и больше не продолжает исследование;
- удары сопровождаются анимацией и всплывающими цифрами урона;
- камера поддерживает zoom in/out и скролл/панорамирование по карте;
- после генерации первого уровня камера стартует сфокусированной на замке и входе в лабиринт с приближенным видом, а не с обзором всей карты;
- клавиши `1`, `2`, `3` переключают скорость времени `x1`, `x2`, `x3`;
- `F1` включает схематичное отображение видимости;
- `F2` включает режим освещенности, скрывающий клетки лабиринта вне суммарной видимости всех героев и свежих трупов за полностью черной темнотой;
- текущая скорость времени отображается в правом верхнем углу;
- после разблокировки нижнего уровня игрок может переключаться между доступными уровнями через отдельный HUD;
- внутриигровая музыка заметно тише SFX, а SFX отличаются по типам игровых событий и HUD-действий;
- `Escape` открывает/закрывает меню паузы, а новая генерация запускается кнопкой старта внутри этого меню;
- камера показывает сгенерированную карту без ручной настройки;
- физический terrain создается вместе с картой, выглядит как земля вне лабиринта, остается видимым в режиме `F2` и не раскрывает скрытые клетки благодаря черной подложке под сеткой лабиринта;
- клик по базе открывает HUD базы;
- HUD базы можно закрыть;
- в Console нет ошибок после запуска и генерации;
- повторный запуск Play Mode снова корректно показывает меню и генерирует карту.

## 15. Рекомендуемый порядок реализации

1. Создать стартовую сцену и добавить ее первой в Build Settings.
2. Создать базовые папки проекта.
3. Реализовать `GameSettings` и меню выбора размера.
4. Реализовать логическую модель `MazeGrid` / `MazeCell`.
5. Реализовать генератор лабиринта без визуализации.
6. Добавить проверку входа и связности проходимых клеток.
7. Добавить renderer для стен, проходов, базы, входа и мобов.
8. Добавить камеру 2.5D и автоподбор обзора.
9. Добавить интерактивность базы и HUD.
10. Проверить несколько ручных размеров, включая `100 x 25`, который нормализуется в `101 x 25`.
11. Почистить Console от ошибок и предупреждений, связанных с MVP.

## 16. Минимальные тесты и проверки

### 16.1. Ручные проверки

- Запустить Play Mode.
- Выбрать маленькую карту и стартовать.
- Проверить наличие базы, входа, обычных мобов и босса.
- Проверить наличие закрытого спуска во второй части лабиринта.
- Кликнуть по базе и открыть HUD.
- Кликнуть по боссу и открыть правый HUD.
- Победить босса, получить ключ спуска, открыть спуск и переключиться на уровень `2`.
- Закрыть HUD.
- Повторить для среднего и большого размеров.
- Несколько раз перезапустить Play Mode и убедиться, что генерация стабильна.

### 16.2. Автоматические проверки, если добавляются тесты

Рекомендуемые EditMode-тесты:

- генератор создает сетку заданного размера;
- на карте есть ровно одна база;
- на карте есть ровно один вход;
- вход находится со стороны базы, но не соприкасается с footprint замка;
- все проходимые клетки достижимы из входа;
- босс появляется на достижимой проходимой клетке;
- закрытый спуск появляется во второй части лабиринта;
- допустимые ручные размеры проходят валидацию.

## 17. Границы MVP

В первый этап не входят, если отдельно не запрошено:

- пошаговое перемещение;
- сложные вражеские фракции за пределами нейтральных мобов;
- сложная экономика базы за пределами стартовых ресурсов, ферм и базовой лавки алхимика;
- сохранение/загрузка;
- процедурные комнаты с разными биомами;
- сложные анимации и финальный визуальный стиль;
- мобильное управление;
- сохранение общей карты между разными запусками игры.

### 12.4. Debug-логирование

Runtime должен писать диагностические сообщения через Unity `Debug.Log` / `Debug.LogWarning` / `Debug.LogError` с единым префиксом `[Labyrinth]`.

Логирование должно быть событийным, без сообщений на каждый шаг героя или каждый кадр.

Обязательные категории:

- `Game` - старт генерации, переход в play mode, пауза и возврат в меню;
- `Maze` - размер, seed, вход, позиция базы, центральная комната, двери, ключ, сундуки, количество и входы пещер, ошибка валидации;
- `Mobs` - количество обычных мобов, разбивка по видам, позиция босса и параметры распределения;
- `Base` - успешная постройка фермы и лавки алхимика, причины блокировки строительства, старт и завершение декоративных дорог;
- `Hero` - создание героя, позиция дома героя, стартовая позиция, стартовые боевые параметры, подбор ключа и открытие сундуков;
- `Combat` - старт боя, поражение моба, награды, уровень героя и смерть героя;
- `Victory` - выполнение условия победы после поражения босса.
- `Mine` - постройка Гильдии шахтёров, вход в режим выбора рудной пещеры, постановка стройзоны, укрепление маршрута, завершение шахты, отправка и доставка шахтных караванов.

## 18. Открытые вопросы

Перед расширением проекта стоит решить:

- будет ли игрок управлять персонажем, камерой или только базой;
- должна ли база быть отдельной областью вне лабиринта или первой клеткой карты;
- нужны ли дополнительные типы боссов и условия победы в будущем;
- должен ли размер карты быть только квадратным или ширина/высота выбираются отдельно;
- нужен ли фиксированный seed в UI для повторяемой генерации;
- какой визуальный стиль выбрать после MVP: низкополигональный, настольная диорама, темное подземелье, техническая сетка.

## 19. Актуальные уточнения UI

- Главное меню должно быть широким и читаемым: крупный заголовок, крупные подписи, кнопки и поля ввода.
- Главное меню поддерживает ручной ввод ширины/высоты в диапазоне `15..101`, без кнопок готовых размеров.
- Значения размера по умолчанию в главном меню: `100 x 25`, отображаемый результат генерации `101 x 25`.
- Ручной размер нормализуется к нечетным значениям перед генерацией, чтобы соответствовать алгоритму лабиринта.
- HUD замка показывает здания и кнопку `Создать героя`, но не показывает список героев.
- Начальные позиции мобов должны распределяться по лабиринту равномерно: каждый следующий моб выбирается как максимально удаленный от уже выбранных позиций и босса, с мягкой минимальной дистанцией между стартовыми позициями.
- Вкладка подземелья в HUD замка содержит `Гильдию шахтёров` и, после её постройки, действие `Шахта`: игрок выбирает изученную малую пещеру с железной или золотой залежью, система ставит стройзону, рабочие укрепляют маршрут от входа по `1 дерево` за клетку, затем шахтёр строит шахту за `10 дерева`.
- Шахтёры визуально выходят из `Гильдии шахтёров` по одному, до `5` активных одновременно, идут к замку только по завершённой дороге, берут дерево в замке, заходят в лабиринт через вход и двигаются только по укреплённому коридору до текущей клетки строительства; перед постройкой шахты они укрепляют все клетки минипещеры `3 x 3` и после работы возвращаются в замок за следующим деревом. Укреплённые клетки всегда дают свет в режиме F2, факелы ставятся с учётом радиуса света и открывают MicroHUD стройзоны/шахты.
- Построенная шахта улучшается через свой MicroHUD: уровень `2` стоит `75 зол., 25 дер., 20 жел.` и повышает размер партии до `15`, уровень `3` стоит `130 зол., 45 дер., 45 жел.` и ускоряет добычу до `+2` ресурса за тик.
